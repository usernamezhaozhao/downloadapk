## Flutter Hello World 项目脚手架（CI 打包）
- 用户要求：本机不装 Flutter/Android SDK，所有脚手架生成、测试、打包都在 GitHub Action 完成；用户自己负责 git push。
- 仓库只放纯文本：`lib/main.dart`(Hello World)、`test/widget_test.dart`、`pubspec.yaml`、`.github/workflows/build-apk.yml`、`.gitignore`、`README.md`。不提交 android/ios 等原生文件。
- 工作流关键设计：CI 内 `flutter create` 生成标准脚手架（自带正确 Gradle wrapper）→ 用我们的源码覆盖 `lib/main.dart`/`test`/`pubspec.yaml` → `flutter pub get` → `flutter test` → `flutter build apk --debug` → 上传 artifact。这样保证原生脚手架与 Flutter 版本一致，避免低级错误。
- 必须的步骤：`setup-java@v4`(JDK17) + `subosito/flutter-action@v2`(stable) + `android-actions/setup-android@v3`(runner 默认无 Android SDK) + 关闭 analytics + 同意 license。打 debug APK 免签名即可安装。
- 修正：`yes | sdkmanager --licenses` 因 sdkmanager 不在 PATH 而静默失效（被 `|| true` 吞掉）；改用 `yes | flutter doctor --android-licenses` 才能正确自动同意全部 Android 许可，否则 build 卡在 `Accept? (y/N):` 失败。
- 二次修正：`android-actions/setup-android@v3` 默认装 `tools platform-tools`，而 `tools` 包 Google 已下架 → `Failed to find package 'tools'` 退出码1。必须升级到 `@v4`（`@v4` 默认 `platform-tools` 且自动同意许可）。这是真正根因。
- 结构优化：构建改在仓库目录(CWD)进行（不再在 /tmp 里构建再 cp），`flutter create` 生成脚手架后只把 `android/` 拷进 CWD，保留自有 lib/test/pubspec。这样标准 APK 路径 `build/app/outputs/flutter-apk/app-debug.apk` 成立，upload-artifact name 设为 `app-apk`，用户可在 Actions 页下载。
- 用户偏好：做任何网络/外网搜索前先说明要搜什么。

## 需求分析：抖音下载器 App（2026-10-11 晚）
- 用户新增 `需求.txt` + `抖音下载使用手册.md`：项目实质是**抖音/TikTok 下载器**。Flutter 前端调用自建后端 `TikTokDownloader`(`http://8.152.206.46:5555`，HTTP 明文，镜像 `qiqi123123123/tiktok-downloader`)拿直链，再把视频/图文存本地。一级需求：粘贴链接下载、图文批量保存、本地列表+播放器播放、标题提取命名、自动分类、下载状态/进度条/通知、Cookie 录入+健康API预检。二级：剪贴板监听、搜索、B站接入。
- 所需 Android 权限：`INTERNET`、`ACCESS_NETWORK_STATE`、存储(`READ/WRITE_EXTERNAL_STORAGE` 旧版；`READ_MEDIA_VIDEO/IMAGES/AUDIO` API33+)、`POST_NOTIFICATIONS`(API33+ 运行时申请)；进阶 `FOREGROUND_SERVICE`(+`FOREGROUND_SERVICE_DATA_SYNC` API34) 后台下载、`WAKE_LOCK`。
- 非权限但必改 manifest 的坑：① 后端是 HTTP 明文 → 必须 `android:usesCleartextTraffic="true"`(或 network security config 只放行该 IP)，否则 Android9+ 请求全失败；② 调系统播放器需注册 `FileProvider`+`file_paths.xml`；③ Android11+ `queries` 声明播放器 intent。运行时申请用 `permission_handler` 包。
- 架构注意：当前 workflow 每次 CI `flutter create` 重生 `android/` → 上述 manifest 改动若固化必须「提交自有 android/ 不再生成」或在 CI 用脚本 patch。真做下载器时建议方案A(提交 android/)。
